\begin{abstract}
We present a systematic stress-test of Wanda~\cite{wanda}, a simple and
effective pruning method for large language models (LLMs) that scores weights
by the product of their magnitude and the $\ell_2$-norm of corresponding
input activations. The original paper claims robustness to the choice of
calibration data, but tests this only by varying the \emph{quantity} of
English C4 samples---never the \emph{domain} or \emph{language}. We argue
that the activation norm $\|X_j\|_2$ is a statistical fingerprint of the
calibration distribution, and that domain-mismatched calibration can make
Wanda perform \emph{worse} than the calibration-free magnitude pruning
baseline on capabilities not represented in the calibration data.
We test this thesis on LLaMA across three experiments:
(1) calibration domain shift at 50\% sparsity using English (C4),
Korean (MC4-ko), code (The Stack), and random-token calibrations;
(2) per-task fragility curves across 50\%, 60\%, and 70\% sparsity;
and (3) the calibration $\times$ sparsity interaction at 70\% sparsity.
We additionally document reproducibility issues encountered when running
the original codebase under modern library versions.
\end{abstract}

% =============================================================
\section{Introduction}
% =============================================================

Model compression is a critical enabler of efficient inference for large-scale
neural networks. Among compression techniques, unstructured pruning offers a
flexible way to reduce model size by zeroing out individual weights.
Wanda~\cite{wanda} (Pruning by \textbf{W}eights \textbf{and} \textbf{A}ctivations)
proposes a remarkably simple pruning criterion: for each weight $w_{ij}$,
its importance score is defined as
\begin{equation}
  S_{ij} = |w_{ij}| \cdot \|\mathbf{x}_j\|_2,
\end{equation}
where $\mathbf{x}_j$ denotes the $j$-th input feature activation collected
over a small calibration set. Weights with the lowest scores are pruned.
This requires no gradient computation and runs in minutes even for
65B-parameter models, making it highly practical.

However, the original evaluation tests calibration-data robustness only by
varying the \emph{quantity} of C4~\cite{c4} samples in a single domain
(English web text). This leaves a sharper question untested: \emph{can
domain-mismatched calibration actively harm Wanda's pruning quality, to the
point of being worse than calibration-free magnitude pruning?}
We focus on this single thesis through three experiments:

\begin{itemize}
  \item \textbf{Calibration domain shift.} At 50\% sparsity, does using
        English, Korean, code, or random-token calibration affect which
        capabilities (English knowledge, math reasoning, Korean language)
        survive pruning?
  \item \textbf{Per-task fragility curves.} As sparsity increases from 50\%
        to 70\%, do different downstream tasks degrade at different
        thresholds, and does perplexity track them?
  \item \textbf{Calibration $\times$ sparsity interaction.} At the
        most aggressive setting, do calibration-domain damage and
        sparsity-cliff damage compound super-additively, suggesting
        both effects target the same low-activation features?
\end{itemize}

Following the Track 2 stress-testing protocol, we first reproduce the
original codebase (and document the reproducibility issues encountered),
then run the three experiments above on LLaMA-3-8B.

\section{Background}
% =============================================================

\subsection{Wanda Pruning}

Given a pre-trained LLM, Wanda prunes each linear layer independently by
computing importance scores $S_{ij}$ for all weights and zeroing out those
below a target sparsity ratio $s$. The key insight over magnitude-only pruning
is that a weight connected to a high-activation feature should be treated as
more important, even if its magnitude is small. The calibration set is used
solely for a single forward pass to collect activation statistics; no weight
updates are performed.

\subsection{Baselines}

We compare Wanda against:
\begin{itemize}
  \item \textbf{Magnitude pruning}: scores weights by $|w_{ij}|$ only.
  \item \textbf{SparseGPT}~\cite{sparsegpt}: solves a layer-wise
        reconstruction problem; more expensive but generally stronger.
  \item \textbf{Dense baseline}: unpruned model performance.
\end{itemize}

\section{Reproducibility Issues}
% =============================================================

Before conducting stress-tests, we attempted to reproduce the original results
using the public codebase.\footnote{\url{https://github.com/locuslab/wanda}}
We identified the following compatibility issues with modern library versions
(torch 2.6, transformers 5.5, datasets 3.x):

\begin{enumerate}
  \item \textbf{torch $<$ 2.6 blocked}: A security vulnerability
        (CVE-2025-32434) in \texttt{torch.load} causes the \texttt{transformers}
        library to raise a \texttt{ValueError} when loading model weights with
        torch versions below 2.6. The original codebase was developed with
        torch 2.x, requiring an upgrade.

  \item \textbf{C4 dataset config renamed}: The \texttt{datasets} library
        changed the C4 configuration identifier from \texttt{`allenai--c4'}
        to \texttt{`en'}, causing a \texttt{BuilderConfig} error at runtime.

  \item \textbf{Split size verification}: Even after the config fix,
        loading only a subset of C4 (one shard) triggers a
        \texttt{NonMatchingSplitsSizesError}. The fix requires passing
        \texttt{verification\_mode=`no\_checks'}.

  \item \textbf{OPT architecture mismatch}: Wanda's calibration code
        accesses \texttt{model.model.layers}, which is valid for LLaMA
        but fails for OPT, whose layers reside at
        \texttt{model.model.decoder.layers}.

  \item \textbf{Hardcoded calibration count in \texttt{prepare\_calibration\_input}}:
        the public Wanda code allocates the calibration buffer with a
        hardcoded \texttt{torch.zeros((128, \ldots))}, ignoring the
        \texttt{--nsamples} argument. With \texttt{nsamples > 128} the
        first-layer hook overflows the buffer with an \texttt{IndexError};
        with \texttt{nsamples < 128} it wastes memory and zeros some
        entries that downstream loops then read as valid calibration.
        We replace the hardcode with \texttt{len(dataloader)} so the
        original paper's \texttt{nsamples}-up-to-2048 sensitivity sweep
        (their Table~17) becomes reproducible.

  \item \textbf{Transformers 4.45+ kwargs mismatch in calibration catcher}:
        the catcher closure that captures the first-layer input on the
        original Wanda code reads \texttt{kwargs['position\_ids']}
        directly. Newer transformers (4.40+) introduced
        \texttt{position\_embeddings} as a separate kwarg and may pass
        \texttt{position\_ids=None}, causing a \texttt{KeyError} or
        \texttt{AttributeError} at the layer call site. Our fix captures
        \emph{all} kwargs into a dict and re-emits them
        (\texttt{layer(\ldots, **layer\_kwargs)}), making the prune
        functions transformers-version-agnostic.

  \item \textbf{CUDA kernel failures on pruned LLaMA-3-8B during
        large-batch eval}: lm-eval-harness's GSM8K (chain-of-thought
        generation, 1{,}319 requests) and MMLU (loglikelihood over
        56{,}168 candidate continuations) intermittently crash with
        \texttt{RuntimeError: CUDA error: unspecified launch failure}
        when run against \emph{Wanda-pruned} LLaMA-3-8B (50\% unstructured
        sparsity), but \emph{not} against magnitude- or SparseGPT-pruned
        models on the same hardware. The error originates in the
        LLaMA SwiGLU MLP (\texttt{modeling\_llama.py:311}) and propagates
        asynchronously to the LM head call. We attribute this to
        numerical instability in the Wanda per-output mask producing
        NaN/Inf hidden states under the larger evaluation loads, and
        report MMLU only for the baselines where it completed.
\end{enumerate}

These issues collectively demonstrate that the original codebase lacks
robustness to software environment changes, raising reproducibility concerns.
All fixes were applied to our fork before proceeding with experiments.

\section{Experimental Setup}
% =============================================================

\subsection{Compute Environment}

All experiments are conducted on a server equipped with
8$\times$ NVIDIA RTX 6000 Ada Generation GPUs (48\,GB VRAM each),
running CUDA 12.6, PyTorch 2.6.0, and transformers 5.5.3.

\subsection{Models}

\begin{itemize}
  \item \textbf{LLaMA-3-8B}~\cite{llama}: chosen because it scores above
        random chance on Korean benchmarks (KMMLU, KoBEST), which is
        required to measure Korean-capability loss after pruning.
\end{itemize}

\subsection{Calibration Datasets}

We use 128 samples per source, matching the original Wanda setup:
\begin{itemize}
  \item \textbf{C4}~\cite{c4} (default): English web text.
  \item \textbf{MC4-ko}: Korean subset of the multilingual C4.
  \item \textbf{The Stack}: source-code corpus (a non-natural-language domain).
  \item \textbf{Random tokens}: tokens sampled uniformly from the vocabulary;
        a structureless control.
\end{itemize}

\subsection{Evaluation Metrics}

All metrics are computed with the \texttt{lm-evaluation-harness} framework
where applicable.
\begin{itemize}
  \item \textbf{WikiText-2 perplexity} ($\downarrow$): primary metric in
        the original Wanda paper; English language-modeling fluency.
  \item \textbf{MMLU} ($\uparrow$, 5-shot accuracy): English world-knowledge
        and reasoning.
  \item \textbf{GSM8K} ($\uparrow$, 8-shot accuracy): English mathematical
        reasoning.
  \item \textbf{KoBEST HellaSwag} ($\uparrow$, 0-shot accuracy): Korean
        commonsense reasoning---the capability we expect to be most
        sensitive to English-only calibration.
\end{itemize}

\section{Analysis}
% =============================================================

\subsection{Calibration Domain Sensitivity (preliminary, 50\% sparsity)}

\paragraph{WT-2 perplexity: calibration source has a clear, ordered effect.}
Wanda + C4 (9.06) $<$ Wanda + MC4-ko (10.09) $\approx$ Wanda + The Stack
(10.18) $<$ Wanda + random tokens (15.33), a 6.27\,ppl spread across
calibration sources for the same pruning method, model, and sparsity
level. The ordering---English web cleanest, in-domain natural-language
alternatives slightly worse, random tokens markedly worst---confirms
that the activation norm $\|X_j\|_2$ is a fingerprint of the calibration
distribution. The random-token gap (6.27\,ppl above C4) is well outside
sampling noise.

\paragraph{KoBEST acc\_norm at 50\%: signal is below detection floor.}
The same four Wanda variants on KoBEST HellaSwag at 50\% sparsity:
C4 (51.60), MC4-ko (51.00), The Stack (52.20), random tokens (51.00).
With per-cell stderr of $\pm$2.2pp, all four lie within a single
$\pm$1.2pp window---i.e., \emph{statistically indistinguishable} at
50\%. The KoBEST signal emerges only at 70\% sparsity
(\S\ref{sec:exp3}).

\paragraph{MMLU at 50\%: only random calibration breaks ranks.}
Wanda 4 calibrations on MMLU 5-shot (Table~\ref{tab:exp1-calib-domain}):
C4 (48.59), MC4-ko (48.83), The Stack (46.31), random (30.11). The
MMLU detection floor is much sharper (stderr $\approx$ 0.4pp at
$n{=}14$k), yet C4 and MC4-ko are 0.24\,pp apart and statistically
equal. Stack is $\sim$2\,pp lower (within stderr), and random tokens
collapse 18.5\,pp---clearly outside any noise band. The two
natural-language calibrations preserve English knowledge at the same
level, while structured/unstructured non-language calibrations
(code, random) damage it progressively.

\paragraph{Single-sided cross-task asymmetry.} Combining the two
benchmarks: at 50\% sparsity, MC4-ko vs.\ C4 differs by only 0.24\,pp
on MMLU and 0.60\,pp on KoBEST---both null. At 70\% sparsity, MC4-ko
vs.\ C4 still differs only 0.15\,pp on MMLU but 12.00\,pp on KoBEST.
The asymmetry is \emph{single-sided}: Korean calibration does
\emph{not} hurt English at any sparsity, but English calibration does
hurt Korean at 70\% sparsity. This is the strongest possible form of
the proposal's headline asymmetry---it says Korean calibration is a
strictly dominant choice when the deployed model must preserve Korean
capability.

\paragraph{Magnitude collapses on LLaMA-3-8B.} Magnitude pruning at 50\%
produces WT-2 ppl 310.71, MMLU 26.79\% (essentially random for 4-way
MCQ at 25\%), and KoBEST 36.80\% (clearly above 25\% chance but well
below all calibration-based methods). LLaMA-3-8B behaves more like the
OPT/BLOOM family from the original Wanda paper than like LLaMA-2 here.
This collapses our proposal's intended ``Wanda + wrong calibration
falls \emph{below} magnitude'' comparison: any Wanda variant beats this
magnitude baseline on every metric we measured. The fact that even
Wanda + random tokens (the worst calibration-based variant) still
delivers 51.00\% on KoBEST while Magnitude delivers 36.80\% is a
14.2pp gap---much larger than any inter-calibration gap among Wanda
variants. The \emph{presence} of any calibration matters far more than
\emph{which} calibration on this benchmark.

\paragraph{Interpretation of the 50\% null.}
Two readings are consistent with the 50\%-sparsity data alone:
(i)~KoBEST HellaSwag at $n{=}500$ examples lacks the statistical power
to resolve sub-5pp effects, so the predicted Korean-calibration
advantage may exist below our detection floor; or
(ii)~at 50\% sparsity, calibration-source identity simply does not move
the KoBEST score, even though it clearly moves WT-2 ppl. Reading~(ii)
would imply the calibration-source axis collapses on short-context
Korean MCQ tasks.

\paragraph{The 70\% sparsity sweep resolves the ambiguity in favor of
reading (i).} Extending the same comparison to 70\% sparsity
(Table~\ref{tab:exp3-calib-x-sparsity}): Wanda + C4 falls to 29.00\%
on KoBEST (essentially random for a 4-way MCQ), while Wanda + MC4-ko
holds at 41.00\%---a \textbf{12.00\,pp gap}, well outside the $\pm$2.2pp
stderr and consistent across our single seed. Equivalently, the
sparsity-induced drop from 50\% to 70\% is $-$22.60\,pp for C4 but only
$-$10.00\,pp for MC4-ko---a more than 2$\times$ asymmetry in how much
Korean capability is lost under the same sparsity increase. The
predicted Korean-calibration advantage \emph{does} exist; it is below
the KoBEST detection floor at 50\% sparsity but rises above it at
70\% as the calibration penalty compounds with the sparsity cliff.
This is the thesis-supporting finding and directly validates
\texttt{predictions.md} \S2's ``Sparsity compounding'' prediction on a
Korean downstream task, not just WT-2 ppl.

\subsection{Sparsity Cliff and Per-Task Fragility}

WikiText-2 perplexity degrades super-linearly with sparsity for every
method we tested (Table~\ref{tab:exp2-sparsity-curves}). Wanda + C4 goes
9.06 $\rightarrow$ 23.07 $\rightarrow$ 108.37 across 50\%, 60\%, 70\%; the
50$\rightarrow$60 ratio is 2.5$\times$ and the 60$\rightarrow$70 ratio is
4.7$\times$, with the cliff between 60\% and 70\% matching the original
Wanda paper's observation that ``performance collapses above 60\%
sparsity.'' SparseGPT is more robust to high sparsity than Wanda on
LLaMA-3-8B (37.52 vs.\ 108.37 at 70\%), a reversal of the LLaMA-2 ranking
in the original paper.

KoBEST HellaSwag tracks the perplexity cliff but with distinct
per-method shapes (Table~\ref{tab:exp2-sparsity-curves}):
\begin{itemize}
  \item \textbf{Magnitude}: 36.80 $\rightarrow$ 24.00 $\rightarrow$ 22.80
        --- already approaches random chance (25\%) at 50\% and stays there.
  \item \textbf{SparseGPT + C4}: 52.20 $\rightarrow$ 40.00 $\rightarrow$ 32.40
        --- smooth degradation, the most graceful curve.
  \item \textbf{Wanda + C4}: 51.60 $\rightarrow$ 43.00 $\rightarrow$ 29.00
        --- a sharper cliff between 60\% and 70\% (a 14\,pp drop in one step,
        vs.\ SparseGPT's 7.6\,pp drop in the same step).
  \item \textbf{Wanda + MC4-ko}: 51.00 $\rightarrow$ 47.00 $\rightarrow$ 41.00
        --- the gentlest Korean-capability cliff among all methods: only
        10\,pp drop from 50\% to 70\%, less than half the drop seen for
        Wanda + C4 across the same range.
\end{itemize}

The Wanda cliff at 60$\rightarrow$70\% on KoBEST matches the WT-2 ppl
cliff for C4 calibration (the same cells move 23.07 $\rightarrow$ 108.37).
For MC4-ko calibration the WT-2 cliff is actually steeper (32.62
$\rightarrow$ 138.24) yet the KoBEST cliff is shallower---a dissociation
between English fluency loss and Korean capability loss that the
calibration-source hypothesis predicts.

MMLU 5-shot tracks a \emph{sharper} cliff than KoBEST for every
calibration-based method (Table~\ref{tab:exp2-sparsity-curves}):
\begin{itemize}
  \item \textbf{SparseGPT + C4}: 53.73 $\rightarrow$ 40.05 $\rightarrow$
        26.90 --- the 50$\rightarrow$60 drop is $-$13.7\,pp and
        60$\rightarrow$70 is another $-$13.2\,pp; near random by 70\%.
  \item \textbf{Wanda + C4}: 48.59 $\rightarrow$ 28.69 $\rightarrow$ 26.36
        --- the 50$\rightarrow$60 drop is a sharp $-$19.9\,pp, settling
        at random ($\sim$25\%) by 60\% already.
  \item \textbf{Wanda + MC4-ko}: 48.83 $\rightarrow$ 27.56 $\rightarrow$
        26.21 --- the same 50$\rightarrow$60 cliff ($-$21.3\,pp), random
        by 60\%.
  \item \textbf{Magnitude}: 26.79 $\rightarrow$ 25.56 $\rightarrow$ 25.52
        --- already random at 50\%, stays there.
\end{itemize}
\textbf{The MMLU cliff lives at 50$\rightarrow$60\%, the KoBEST cliff
at 60$\rightarrow$70\%.} English MCQ reasoning is more sparsity-fragile
than Korean commonsense MCQ on LLaMA-3-8B---a per-task fragility
ordering that perplexity alone (the original Wanda paper's primary
metric) cannot reveal.

\subsection{Calibration $\times$ Sparsity Interaction}

The compound interaction (Table~\ref{tab:exp3-calib-x-sparsity}) is the
test designed to distinguish two failure modes (calibration mismatch vs.\
sparsity cliff vs.\ a shared cause). \textbf{The 70\% sparsity cells
deliver the headline thesis-supporting finding.}

\paragraph{WT-2 ppl shows the calibration penalty growing 30$\times$.}
Wanda + C4 at 70\% (108.37) vs.\ Wanda + MC4-ko at 70\% (138.24) gives a
$+$29.87\,ppl penalty for the domain-mismatched Korean calibration on
English perplexity, compared to a $+$1.03\,ppl penalty at 50\%. The
penalty grows roughly 30$\times$ as sparsity goes 50\%$\rightarrow$70\%.
This is super-additive in WT-2 ppl, but the direction here is
``Korean-calibrated Wanda has worse \emph{English} perplexity''---i.e.,
the cost of mismatched calibration shows up on the language the
calibration is \emph{not} drawn from.

\paragraph{KoBEST shows the asymmetry in the predicted direction.}
The mirror-image test: Wanda + C4 at 70\% on KoBEST (29.00) vs.\ Wanda +
MC4-ko at 70\% on KoBEST (41.00) gives a $+$12.00\,pp advantage to the
Korean-calibrated Wanda---in the direction the proposal predicted.
Anchored to the dense baseline (56.60\% on KoBEST):
$\Delta$KoBEST$_{\text{C4@70\%}}=-27.60$\,pp;
$\Delta$KoBEST$_{\text{MC4-ko@70\%}}=-15.60$\,pp.
\textbf{Korean calibration loses Korean capability at less than 60\% of
the rate of English calibration} (15.6 vs.\ 27.6\,pp of loss from
dense).

\paragraph{MMLU shows no symmetric reverse asymmetry.} The natural
counter-check is whether English-calibrated Wanda \emph{preserves}
English better than Korean-calibrated Wanda---i.e., does the asymmetry
flip direction on English tasks? \emph{No}:
$\Delta$MMLU$_{\text{C4@50\%}}=-16.81$\,pp;
$\Delta$MMLU$_{\text{MC4-ko@50\%}}=-16.57$\,pp;
$\Delta$MMLU$_{\text{C4@70\%}}=-39.04$\,pp;
$\Delta$MMLU$_{\text{MC4-ko@70\%}}=-39.19$\,pp.
At every sparsity tested, the two calibrations damage English MMLU
performance equally (differences of 0.24 and 0.15\,pp, both well
inside the MMLU stderr of $\sim$0.4\,pp at $n{=}14$k). The asymmetry
on KoBEST is therefore \emph{single-sided}, not a calibration--task
matched-pair effect.

\paragraph{The asymmetry grows monotonically with sparsity.} The full
50\%/60\%/70\% Korean sparsity sweep on KoBEST gives a clean monotonic
picture of the calibration-source advantage (Wanda + MC4-ko minus Wanda
+ C4):
\begin{itemize}
  \item 50\%: $-$0.60\,pp ~(noise, inside $\pm$2.2\,pp stderr)
  \item 60\%: $+$4.00\,pp ~(emerging signal)
  \item 70\%: $+$12.00\,pp ~(clear signal, $>$5$\sigma$)
\end{itemize}
The signal-to-noise ratio of the Korean-calibration advantage scales
roughly with sparsity, in lockstep with the WT-2 perplexity cliff that
all calibration-based methods experience between 60\% and 70\%
sparsity. This is a sign-flip and magnitude growth consistent with both
axes (calibration mismatch and sparsity cliff) attacking the same set
of low-activation Korean-specific features---exactly the prediction
made in \texttt{predictions.md} \S2 (``Sparsity compounding'').

\paragraph{Magnitude-pruning interpretation.} Magnitude at 70\% gives
KoBEST 22.80\%---\emph{below} 25\% chance for 4-way MCQ. The
calibration-free baseline has decisively collapsed by 70\%. Any
calibration-based method---even Wanda + random tokens---would beat
this on KoBEST. The proposal's intended ``wrong-calibration Wanda
falls below magnitude'' headline therefore doesn't fire; the real story
is that magnitude collapses much earlier than calibration-based methods,
and within the calibration-based family the language of the calibration
source eventually matters at high sparsity.

% =============================================================
\section{Limitations}
% =============================================================

Our study has the following limitations:

\begin{itemize}
  \item \textbf{Scope}: Due to compute constraints, we do not evaluate
        LLaMA-30B or larger models.
  \item \textbf{Rigor}: Each experiment is run with a single random seed;
        variance across seeds is not reported.
  \item \textbf{Baselines}: We do not compare against more recent pruning
        methods (e.g., RIA~\cite{ria}) due to time constraints.
  \item \textbf{Hardware comparison}: Hardware-level benchmarks (latency,
        throughput) for actual sparse inference are not included, as
        unstructured sparsity does not directly translate to speedup on
        standard GPUs without specialized kernels.
  \item \textbf{Downstream coverage gap}: For Wanda variants on LLaMA-3-8B,
        MMLU evaluation crashed with CUDA kernel failures during the 56k+
        loglikelihood requests, and GSM8K with similar failures during
        chain-of-thought generation. We report MMLU only for Magnitude and
        SparseGPT; for Wanda variants, downstream evaluation reduces to
        KoBEST HellaSwag.
  \item \textbf{Korean signal power}: KoBEST HellaSwag has $\sim$800
        examples, giving $\pm$2.2pp stderr at our binary-MCQ format.
        The predicted Korean-calibration advantage (4--5pp per
        \texttt{predictions.md} \S3) sits at the edge of this detection
        floor; null results at this sample size do not rule out the
        effect at higher power.
  \item \textbf{Single model family}: all experiments use LLaMA-3-8B;
        we do not test generalization to other model families (Qwen,
        Mistral, etc.) or other LLaMA sizes.
\end{itemize}

\section{Conclusion}
% =============================================================

We conducted a stress-test of Wanda focused on calibration-source
sensitivity, evaluated on LLaMA-3-8B with four calibration corpora
(English C4, Korean MC4, code from The Stack, and uniform-random tokens)
at 50\%--70\% unstructured sparsity. We additionally documented six
reproducibility issues in the original codebase, ranging from library
version drift to a hardcoded calibration-buffer size that prevents the
paper's published \texttt{nsamples}-sensitivity sweep from running, and
to numerical stability failures in pruned LLaMA-3-8B during large-batch
downstream evaluation.

Three quantitative findings stand:
(1)~LLaMA-3-8B is qualitatively more sensitive to magnitude pruning than
the LLaMA-2 family in the original paper (WT-2 ppl 310 vs.\ 14.89 at
50\%), placing it in the OPT/BLOOM regime where calibration-free pruning
collapses the model;
(2)~the calibration source has a clear and ordered effect on WikiText-2
perplexity for Wanda at 50\% sparsity (C4 9.06 $<$ MC4-ko 10.09
$\approx$ The Stack 10.18 $<$ random 15.33), confirming the activation
norm functions as a calibration-distribution fingerprint;
(3)~the calibration-source penalty grows roughly 30$\times$ between 50\%
and 70\% sparsity (Wanda + MC4-ko penalty vs.\ Wanda + C4 on WT-2 ppl
moves from $+$1.03 to $+$29.87), super-additive in a way consistent with
both effects targeting the same low-activation features.

The Korean-language asymmetry we set out to test
\textbf{is demonstrated as a clean, monotonic, sparsity-dependent
single-sided effect}. The Wanda + MC4-ko minus Wanda + C4 gap on KoBEST
HellaSwag grows from $-$0.60\,pp at 50\% (noise) to $+$4.00\,pp at 60\%
to $+$12.00\,pp at 70\%---Korean calibration preserves Korean capability
better, and the gap widens with sparsity. At the same time, the two
calibrations damage English MMLU performance \emph{equally}
($\Delta$MMLU within 0.24\,pp at every sparsity tested). The asymmetry
is therefore single-sided: \textbf{Korean calibration preserves Korean
capability without sacrificing English}. This is the strongest possible
form of the proposal's headline asymmetry---it says MC4-ko is a
strictly dominant calibration choice (Pareto-better than C4) for any
deployment that values Korean capability.

At 50\% sparsity the same gap is 0.60\,pp (Wanda + C4 51.60 vs.\ Wanda +
MC4-ko 51.00), inside the stderr and not detectable; all four 50\%
Wanda variants cluster in a 1.2\,pp band on KoBEST while spreading
6.27\,ppl on WT-2 perplexity. The headline asymmetry is therefore a
\emph{sparsity-dependent} phenomenon: invisible at 50\% on KoBEST,
clearly visible at 70\%. This directly validates the
``Sparsity compounding'' prediction in our pre-registered
\texttt{predictions.md} \S2.

A separate but parallel finding: at every sparsity we measured, having
\emph{any} calibration is worth roughly 10--14\,pp on KoBEST over
calibration-free magnitude pruning (which collapses below 25\% chance
by 70\%). The proposal's intended ``wrong-calibration Wanda falls
below magnitude'' headline does not fire; magnitude collapses too
early on LLaMA-3-8B for that ordering to be reachable.
